# De-duplication report (blueprint P1.5)

Generated by `python -m src.make_docs` from `data/processed/build_summary.json`.

## Method
* **Exact duplicates:** SHA-256 of the normalised token string (comments removed, literals -> `<STR>`/`<NUM>`,
  user-defined identifiers -> `<ID>`, so renamed copies count as exact duplicates). One representative per hash
  is kept; the group size is stored in `exact_group_size`.
* **Near duplicates:** MinHash (128 permutations, datasketch) of token
  5-gram shingles; locality-sensitive hashing for candidate pairs; a pair is confirmed when
  the MinHash Jaccard estimate is >= 0.8; connected components (union-find) form the
  clone groups. All 120,510 filtered contracts are covered (no subset was needed): near-duplicate pairs are
  searched among the 65,058 unique contracts, and every exact copy joins the group of its representative.
* **Split:** whole groups go to train / validation / test (70/15/15) with greedy multi-label stratification.
  Groups larger than 1% of the pool always go to train. Without this rule two
  template families (1,194 near-identical "DeltaPay" contracts, all reentrancy; 958 plain "Token" contracts,
  almost all clean) made up about 20 % of the validation and test splits, so thresholds would have been tuned
  to - and scores measured on - single templates instead of new contracts.
